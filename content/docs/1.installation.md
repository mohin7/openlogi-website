# Installation

OpenLogi ships as a native desktop application. Installation has two parts: the
package itself, and a one-time permission step that lets the app reach your
hardware without running as root.

## Requirements

- A 64-bit Linux system with `systemd` (for the `uaccess` permission mechanism)
- A Logitech device that speaks HID++ — anything using Bolt, Unifying,
  Lightspeed, Bluetooth, or a direct USB cable
- Wayland or X11; both are fully supported

## Install the package

::code-group

```bash [Debian / Ubuntu]
sudo apt install ./openlogi_0.1.0_amd64.deb
```

```bash [Fedora / RHEL]
sudo dnf install ./openlogi-0.1.0-1.x86_64.rpm
```

```bash [AppImage]
chmod +x OpenLogi_0.1.0_amd64.AppImage
./OpenLogi_0.1.0_amd64.AppImage
```

::

Downloads are on the
[releases page](https://github.com/mohin7/openlogi/releases/latest).

The `.deb` and `.rpm` packages run the permission setup automatically as part of
installation. If you use those, skip ahead to [First run](#first-run).

::callout{icon="lucide:triangle-alert"}
**The AppImage runs no install script**, so the udev rule is not added for you
and the app will not see your devices until it is. Follow
[Permission setup](#permission-setup) below, then log out and back in. There is
no AUR package yet.
::

## Build from source

You need a Rust toolchain, Node.js 20 or newer, and `pnpm`.

```bash
git clone https://github.com/mohin7/openlogi
cd openlogi
./scripts/setup.sh
```

`setup.sh` asks for `sudo` exactly once, then installs build dependencies and
the udev rule together. Afterwards:

```bash
pnpm install
pnpm app:build
```

## Permission setup

This is the only step that needs root, and it only happens once. It installs a
udev rule that does two things:

**Grants you access to Logitech HID endpoints.** The rule tags Logitech
`hidraw` nodes with `uaccess`, which makes `systemd-logind` attach an ACL for
whoever is logged in at the physical seat. The access is granted at login and
revoked at logout.

**Grants write access to `/dev/uinput`.** Remapped buttons are delivered by
synthesising input events, which requires writing to `uinput`. OpenLogi creates
a dedicated `openlogi` group for this rather than using the conventional `input`
group — see [Permissions](/docs/permissions) for why that distinction matters.

If you installed from a package, this already ran. To do it manually:

```bash
sudo ./scripts/install-udev-rules.sh
```

::callout{icon="lucide:info"}
Group membership only applies to **new** login sessions. After the first
install, log out and back in — or start the app once with
`newgrp openlogi` to test immediately.
::

### Verify it worked

```bash
# Expect a "user:" ACL entry for your username
getfacl -p /dev/hidraw0 | grep '^user:'

# Expect group "openlogi"
ls -l /dev/uinput
```

If `/dev/uinput` does not exist at all, the kernel module is not loaded:

```bash
sudo modprobe uinput
```

The install script writes `/etc/modules-load.d/openlogi.conf` so this happens
automatically on every boot.

## First run

Launch OpenLogi from your application menu, or run `openlogi` from a terminal.
Connected devices appear automatically — there is no pairing or sign-in step.

If your device does not appear, work through
[Troubleshooting](/docs/troubleshooting).
